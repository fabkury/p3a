# RUN-20260828-03 — baseline soak, ABORTED after ~25 min (diag build glitch)

- Diag build 1c783c54, playset "Work mix", 14:09–14:35 local.
- Fab observed a one-frame blue flash every 3–8 s on all animations, present
  since the first diag build of the day and never before. Cause: the reporter's
  per-second `uxTaskGetSystemState()` holds the kernel lock in a critical
  section (interrupts off on core 0) for 3–4 ms (measured via the `snapshot`
  marks: 2956–4213 us) while walking 37 tasks and scanning stacks; the DSI vsync
  ISR lives on core 0, so ~20 % of the snapshots collide with a vblank → a bad
  frame every ~5 s. Not visible to the frame trace (the consumer is on time;
  the panel shows garbage).
- Fix: task table built by one full snapshot at init (+8 s), rebuilt only when
  the task count changes or at stall-report time (marked); per-second poll
  reads run-time counters via `vTaskGetInfo(h, &st, pdFALSE, eBlocked)` (no
  stack scan, microseconds).
- Lesson for the work stream (H-new): ANY interrupts-off window of a few ms on
  core 0 can cost a frame on the glass without showing up as lateness. Worth a
  provoke kind later (`cpu0_critical`) and an audit of critical sections in
  release code paths (flash ops are the obvious one, H1).
