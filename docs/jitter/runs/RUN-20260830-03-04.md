## RUN-20260830-04-idle-exp — the mechanism, confirmed
- Hypothesis: after every write IDF's `sdmmc_wait_for_idle()` polls CMD13
  back-to-back with no yield for the first 100 ms; with the card busy 1–45 ms
  per block, each write is a storm of hundreds of host commands, and both
  cores' decode/upscale crawl for its duration.
- Test: diag-only `--wrap=sdmmc_wait_for_idle` that polls once and then once
  per tick. Bounce-write provocation (PSRAM-misaligned 32 KB × 8, the
  reproducer that gave 6–9 anomalies and up to 535 ms upscale on every
  previous build), 3 rounds on the pinned bar GIF: **0 anomalies, upscale
  max 18 ms**. Spin control 0. Baseline 0 / 3065.
- Verdict: the CMD13 poll storm during card-busy is the root physics behind
  every SD-correlated stall since day 1 (bounce loop, cache-flush bursts,
  verify-sweep storms, fread sector storms, slow-card download writes). Fixes
  1–6 removed the sources; fix 8 removes the mechanism.
- Fix 8: `components/sd_idle_wait/` links a yielding replacement in EVERY
  build (release included; frame_trace marks vanish when trace is off).
